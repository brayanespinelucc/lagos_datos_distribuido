# Viabilidad del laboratorio remoto

Consulta documental del 25 de noviembre de 2026, hora de Bogotá. El perfil Docker se probó en el entorno asignado. Las cifras de productos externos proceden de sus proveedores y deben revisarse si cambia el plan. Una especificación pública acredita la oferta. La posibilidad de desplegar en una cuenta concreta depende de su habilitación, cuotas, región y permisos. [Mediciones del entorno](../../evidence/block-00/entorno.json)

## Herramientas abiertas

| Herramientas | Disponibilidad y uso |
|---|---|
| Docker Engine, Kubernetes y Helm | Se pueden usar como software abierto en un host compatible y autorizado. Docker rootless se probó en la sesión. Los kernels, cgroups, red, almacenamiento y privilegios necesarios se evalúan para cada clúster. Helm construye paquetes y permite renderizar objetos sin crear pods. No aportan hardware adicional ni garantizan que un manifiesto pueda planificarse. [Docker](https://docs.docker.com/engine/security/rootless/) · [RKE2](https://docs.rke2.io/install/requirements) · [Helm](https://helm.sh/docs/topics/charts/) |
| Graphviz, Mermaid y draw.io | Grafican modelos editables sin contratar servicios. Graphviz está instalado y produce los SVG/PNG del proyecto a partir de DOT. Mermaid es una alternativa textual. draw.io Desktop guarda diagramas localmente. CPU y disco son los del editor o del runner. El lector puede abrir los recursos exportados en el navegador sin cuenta. [Graphviz](https://graphviz.org/documentation/) · [Mermaid](https://mermaid.js.org/intro/) · [draw.io](https://github.com/jgraph/drawio-desktop) |
| Playwright y Chromium | La sesión dispone de ambos. Permiten recorrer páginas y capturar estados de la aplicación. Se inicia un navegador aislado y se exportan capturas tras las aserciones. El profesor sólo necesita un navegador ordinario para acceder a los archivos publicados. [Playwright](https://playwright.dev/python/docs/intro) |
| Pandoc, Poppler, Python y FFmpeg | La inspección encontró Pandoc, Poppler, python-docx, python-pptx, ReportLab y FFmpeg/ffprobe. Las salidas son archivos portables; imágenes, clon de Chromium y video requieren parte del disco y CPU de la sesión. La persistencia se obtiene al incorporar los archivos al paquete. [Sondeo](../../evidence/block-00/entorno.json) · [Pandoc](https://pandoc.org/MANUAL.html) · [FFmpeg](https://ffmpeg.org/documentation.html) |

## Estrategia aplicada

| Modalidad | Aplicación | Límite de la afirmación |
|---|---|---|
| A. Host remoto completo | Aprovisionar ocho VM cuando exista un servidor con Proxmox y virtualización autorizada. | El host requerido por el PDF se acredita con acceso a su hipervisor y a los invitados. |
| B. Componentes en el entorno conectado | Ejecutar clúster MinIO de procesos, HAProxy y servicios de datos por bloques. | La unidad que se detuvo, el almacenamiento, las versiones y la red reales figuran en cada ensayo. |
| C. Laboratorio efímero o CI | Repetir configuración, pruebas, ingesta y build. Exportar logs, resultados y descargas antes de finalizar. | El informe de una ejecución sólo se fecha cuando existe el registro. |
| D. Infraestructura reproducible | Inventario, aprovisionamiento, Cloud-init, archivos de RKE2, balanceo, controles y validación. | Renderizado, sintaxis y admisión de objetos cubren criterios distintos al despliegue de las VM y al estado Ready. |
| E. Consulta remota | Servir evidencia, catálogo y documentos y ofrecer descarga para correo. | Los módulos identifican datos observados, modelo simulado y arquitectura propuesta. Un servicio administrativo sólo se considera disponible durante un ensayo registrado. |
